DECODER CONSTRAINT (new): rejects "==" double pad. plaintext len %3==1 -> throw
("Invalid base64 encoding"). Payloads must have decoded len %3 in {0,2}.

LIVE CONTAINER PROBE (port 32367) — confirms canary wall
--------------------------------------------------------
  L=200,260,264  http=200 "Invalid credentials."   (canary intact, returns)
  L=272,280,288  http=500 (lighttpd)               (__stack_chk_fail abort)
  => HARD WALL at offset 264. Any write >=272 corrupts canary -> 500, no flag.

CANARY: changes every exec (3 gdb runs: 0x29d8.., 0x57dc.., 0xe7ff..).
mod_cgi execve's fresh process per request -> fresh canary. Byte-brute across
requests INFEASIBLE (no accumulation). Also decode's trailing '\0' clobbers the
byte after last data -> complicates partial brute even if canary were stable.

ATTACKS DEBUGGED & BLOCKED
--------------------------
1. ret2win / ROP (overwrite saved_rip @280): blocked — must cross canary @264,
   canary fresh per request, no leak. LIVE-confirmed (500 at >=272).
2. exploit.py "overwrite flag[] so strcmp passes": flawed — (a) assumes -O2
   inlining (false, -O0, separate frames); (b) flag@decoded+320 is past canary
   (unreachable); (c) even if reached, main would puts() OUR bytes not real flag.
3. Redirect supplied_password ptr to flag (compare flag==flag): blocked — colon
   pinned at offset 5 (username must be exactly "admin"), so password=decoded+6
   fixed; cannot relocate. flag-ptr slot is BELOW buffer, unreachable.
4. Leak flag via strcmp oracle: strcmp is EQUALITY-ONLY (no prefix/partial). flag
   constant across requests but no per-byte oracle. Timing channel = ~1 strcmp
   iter (~ns) under CGI fork jitter (~ms) -> not measurable. No memory ever
   echoed (only fixed strings / flag / 500). NO in-band leak exists.

CONCLUSION
----------
Overflow alone cannot win on standard infra (canary wall, fresh canary, no leak).
Open avenues (in priority):

 B. Re-examine for any disclosure primitive (none found in source/binary).
 C. Park as hard; bank cheaper flags first.
